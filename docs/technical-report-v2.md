# 文享内江：AI 帮助银龄居民找文化课

版本：2.0，日期：2026-10-07。项目使用演示数据，不是文化馆官方报名平台。

## 我们想解决什么

居民看课程文章时，要自己理解介绍、筛时间、比较费用，再记住报名和上课安排。老年用户可能更习惯说一句“我不会写毛笔字，想试试免费的课”，而不是在很多筛选框中操作。

文享内江把课程列表、预约和课表放到一起，让 AI 把这句话变成可检查的条件。最终能否参加，由实际课程数据和报名规则决定。

## 已完成的功能

- 居民端：浏览、搜索、详情、确认预约、取消、候补和我的课程。
- AI 端：口语需求解析、否定条件识别、预算与时间筛选、前三门推荐、理由、排除原因、补充问题和简明介绍。
- 管理端：演示登录、新增课程、发布下架、CSV 导入与报名名单导出。
- 界面：原创牛肉面 SVG、内江城市主题、大按钮、移动端单列和大字模式。
- 运行：本地 Node.js + SQLite；公网 Cloudflare Pages + D1。提供原生小程序源码，尚未正式发布到微信。

## 一个完整使用流程

1. 用户输入需求或浏览课程。
2. 模型提取兴趣、排除内容、时间、难度、预算等 JSON 字段。
3. 校验 JSON 后，程序检查每门课程的全部课次、名额和个人课表。
4. 展示前三门合格课程及理由；没有结果时解释原因。
5. 用户查看详情并确认预约；满额课程可从列表加入候补。
6. 用户在我的课程查看安排，取消后由报名逻辑处理递补。

## AI 为什么有实际作用

Qwen3 可以理解“毛笔字”“不用花钱”“不想学音乐”这类口语表达，输出标准条件；课程介绍也可以改成短句，降低阅读负担。程序负责检查条件和报名，防止模型编造课程或修改固定事实。

模型：Cloudflare Workers AI 的 `@cf/qwen/qwen3-30b-a3b-fp8`。没有自行训练大模型。本项目自主实现需求协议、字段校验、共享推荐模块、冲突和候补规则、失败回退、前后端与本地文化界面。

## 用到的算法

**需求提取**：提示词约束加 JSON 校验。兴趣使用白名单；星期、时段、预算限制类型与范围；未知字段直接拒绝。失败时用关键词、同义词和否定词规则解析。

**条件过滤**：逐门检查兴趣、排除内容、费用、难度、地点和全部上课时间。按北京时间处理星期与时段。逐门检查与已报名课程是否有重叠，重叠公式为 `已有开始 < 新课结束 && 已有结束 > 新课开始`，相邻不重叠。

**加权排序**：对已符合硬条件的课程计算兴趣、难度、课次检查、费用、余位和地点等得分，降序取前三门；同分按编号排序。得分与理由可以查看，不能把规则分当作适合概率。

**报名与递补**：校验有效报名唯一性、课程状态和报名窗口；在数据库写入时检查容量及全部课次冲突。取消产生空位后按候补顺序选择无冲突用户。线上使用 D1 数据库触发器与批量事务，本地使用 SQLite 事务。

**失败回退**：模型请求设置超时；错误或输出不合格时显示规则模式。浏览与报名不依赖模型返回。

## 架构和数据

浏览器与小程序使用统一 API。共享 `assistant.mjs` 同时供 Node.js 和 Pages 使用。公网通过私有 Worker 调用 AI，不把密钥放到前端。本地默认仅将找课文字或介绍发送给线上 AI；本地课表和报名留在本机。

数据库包含用户、课程、课次、报名、候补和操作记录。线上与本地是独立演示数据库；示例课程来自项目提供的演示数据，未声称来自文化馆授权接口。
